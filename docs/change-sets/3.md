# Change-set for #3 — Track and display click count per shortened link

## Scope

Implement the full link-shortener feature set (shorten, redirect, list) with a `clicks` column baked into the initial SQLite schema, so every redirect atomically increments the counter and the index page shows the count alongside each link. Out of scope: unique-visitor dedup, time-series analytics, per-link detail pages, export/CSV.

## Files to touch

- **Create: `store.go`** — SQLite storage layer; defines `Link` struct, `Store` type, and methods `Save`, `Find`, `IncrementClicks`, and `List`.
- **Create: `handler.go`** — HTTP handlers: `handleIndex` (GET `/`), `handleShorten` (POST `/shorten`), `handleRedirect` (GET `/:code`).
- **Modify: `main.go`** — Open the SQLite DB, construct a `Store`, register all routes, and start the server.
- **Create: `static/index.html`** — Minimal HTML form to shorten a URL; table below it lists all existing links with short code, original URL, and click count.
- **Create: `store_test.go`** — Unit tests for `Save`, `Find`, `IncrementClicks` (including concurrent increments), and `List`.
- **Create: `handler_test.go`** — HTTP-level tests for shorten (happy path + missing URL), redirect (301 + unknown code → 404), and click count increment via redirect.
- **Modify: `go.mod` / add `go.sum`** — Add `modernc.org/sqlite` (pure-Go SQLite driver, no CGO).

## Public API / contract changes

**HTTP endpoints introduced (none existed before):**

| Method | Path        | Success status | Notes                                  |
|--------|-------------|----------------|----------------------------------------|
| GET    | `/`         | 200            | HTML page: form + link listing         |
| POST   | `/shorten`  | 303            | Form field `url`; redirects to `/`     |
| GET    | `/:code`    | 301            | Permanent redirect; increments counter |
| GET    | `/:code`    | 404            | Unknown code                           |
| POST   | `/shorten`  | 400            | Missing or empty `url` field           |

**Database schema (new table):**

```sql
CREATE TABLE IF NOT EXISTS links (
    code   TEXT    PRIMARY KEY,
    url    TEXT    NOT NULL,
    clicks INTEGER NOT NULL DEFAULT 0
);
```

**`Store` public interface (new):**

```go
func NewStore(db *sql.DB) (*Store, error)
func (s *Store) Save(url string) (code string, err error)
func (s *Store) Find(code string) (url string, err error)
func (s *Store) IncrementClicks(code string) error
func (s *Store) List() ([]Link, error)

type Link struct {
    Code   string
    URL    string
    Clicks int
}
```

## Test plan

**New tests — `store_test.go`:**
- `TestSave` — save a URL, verify returned code is 6 alphanumeric chars and `Find` returns the same URL.
- `TestFindUnknown` — `Find` on a nonexistent code returns `sql.ErrNoRows` (or a wrapped sentinel).
- `TestIncrementClicks` — save a link, call `IncrementClicks` three times, verify `List` shows `Clicks == 3`.
- `TestConcurrentIncrements` — 50 goroutines each call `IncrementClicks` on the same code; final count must equal 50 (validates no lost updates under concurrency).
- `TestList` — save two links, confirm both appear in `List` output.

**New tests — `handler_test.go`:**
- `TestHandleShorten_OK` — POST with valid URL returns 303 redirect to `/`.
- `TestHandleShorten_MissingURL` — POST with empty `url` returns 400.
- `TestHandleRedirect_OK` — GET `/:code` for a known code returns 301 with correct `Location`.
- `TestHandleRedirect_NotFound` — GET `/:code` for unknown code returns 404.
- `TestHandleRedirect_IncrementsClicks` — GET `/:code` three times; then GET `/` body contains `3` adjacent to the short code.

**Existing tests:** none exist yet; the above are the first suite.

## Risk justification

The change introduces a database schema (`links` table with a `clicks` column), which the rubric unconditionally classifies as high. It also adds a new runtime dependency (`modernc.org/sqlite`), a second high-risk trigger.

## Open questions

- **Collision handling in `Save`:** If a generated 6-char code collides with an existing one, should the implementation retry (preferred) or return an error? The issue is silent; retry up to N times is the safe default.
- **Persistence path:** Where should `links.db` be written? The issue doesn't specify; a sensible default is the current working directory, overridable via a `DB_PATH` env var (consistent with `PORT`).
- **Redirect type:** The issue says 301 (permanent); CLAUDE.md confirms 301. Browsers cache 301s aggressively, which can mask click counting during manual testing. This is noted but left as-is per spec.
